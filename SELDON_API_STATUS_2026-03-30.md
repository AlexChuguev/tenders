- Слой `download` через внешние площадки не является надёжным.
- Одни площадки скачиваются нормально, другие:
  - требуют browser fallback
  - отдают `403`
  - открывают страницу без явной кнопки скачивания
  - ведут себя по-разному на VPS и на локальном Mac

Вывод: главный нестабильный слой сейчас не `LLM` и не `prepare`, а именно скачивание документов с внешних площадок.

## Текущий рабочий вывод

Рациональный режим работы:

1. `prepare` можно использовать для поиска и формирования батча.
2. Документы лучше скачивать вручную.
3. После ручного скачивания имеет смысл гонять только `review` по уже лежащим файлам.

То есть практический контур сейчас такой:

1. Получить тендеры через `Seldon API` или из `Seldon.Pro xls`.
2. Разложить тендеры по папкам.
3. Скачивать документы вручную.
4. Прогонять только анализ по готовым файлам.
5. Писать результат в `tender_analysis.xlsx`.

### 5. `tender_agent/analysis.py`

- `.doc` разбирается через `textutil`
- `xlsx` извлекается не вслепую, а более осмысленно

### 6. `prompt_template.md`

- Формализованы критерии:
  - `100%` попадание по стеку: `Python`, `React`, `Flutter`
  - оборот компании: `30 млн`
  - требования по обороту и аналогичным проектам надо явно вытаскивать
- `summary` теперь короткий:
  - `1. Риски`
  - `2. Стек`
  - `3. Требования к контрагенту`
  - `4. Документация`
  - `5. Оплата и обеспечение`
- Из `summary` убран нейтральный мусор типа:
  - `требования по обороту отсутствуют`
  - `банковская гарантия не требуется`
  - `другие технологии не указаны`
- Если тендер непрофильный и не про разработку ПО, анализ должен быть коротким и более жёстким.
